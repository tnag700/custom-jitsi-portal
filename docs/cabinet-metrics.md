# Метрики кабинетов

Один общий блок над содержимым всех авторизованных кабинетов показывает доступность
backend, приблизительную загрузку CPU/RAM и состояние свободного места. Общие
проценты округлены до ближайших 5 пунктов. Доступность backend означает успешный
scrape, а не исправность видеосвязи. Гости приглашений и страницы входа не получают
статистику. Значения, которых нет или которые устарели, не заменяются нулями.

`/admin/metrics` доступен только роли `admin`. Администратор выбирает до 12
показателей из проверенного каталога, меняет вид и порядок, сохраняет свой набор.
Настройки принадлежат паре tenant + subject из проверенного principal. Пустой набор
сохраняется; конфликт ревизии возвращает 409 и не перезаписывает чужое изменение.
Настройки работают и при отключённом мониторинге.
Сброс к начальному набору меняет локальный черновик: ревизия сохраняется,
для записи по-прежнему требуется явное сохранение.

## Источники и границы

Используется Prometheus из существующего monitoring overlay. Grafana для этого
дашборда не требуется и не встраивается в кабинет. Без overlay
`APP_METRICS_PROMETHEUS_BASE_URL` пустой, сводка показывает отсутствие мониторинга.
URL принадлежит конфигурации развёртывания; пользователь не задаёт PromQL, labels,
адреса или правила раскрытия данных. Метрики относятся ко всему текущему backend
и VM; environment в адресе админки их не переключает.

node_exporter закреплён на
`quay.io/prometheus/node-exporter:v1.12.1@sha256:1b4e4438faca4dd7e001dd445d161a4a2091b0fededa84093b3a8dfeae1f1be0`.
Источники версии и реализации: [официальный релиз](https://github.com/prometheus/node_exporter/releases/tag/v1.12.1),
[filesystem collector](https://github.com/prometheus/node_exporter/blob/v1.12.1/collector/filesystem_linux.go).
Включены только CPU, meminfo и filesystem системного раздела. Сервис не публикует
9100, не получает Docker socket, host network, privileged или capabilities.
Read-only `/proc` даёт данные VM; `/etc/ssl/certs` используется только как точка
`statfs` того же системного раздела. До выпуска обязательно подтвердить, что этот
путь находится на `/`, не имеет дочерних mounts и даёт показатели VM.

Backend разрешает четыре одновременных HTTP-запроса источника, ограничивает
connect до 1 с, полное чтение до 2 с и выдачу snapshot до 3 с. Ответ источника —
не более 1 MiB, тело настроек — 16 KiB до разбора JSON. Redirection и retries
отключены. Текущие значения кэшируются 30 с с общим обновлением, история — 60 с
и не более 60 комбинаций id/period на backend. Одновременные читатели одного
графика используют один запрос; прерывание читателя не отменяет его для остальных.

Свежесть определяется timestamp исходного sample, а не временем вычисления
Prometheus. Sample старше 90 с или down-target не изображается исправным.
Свежий `up` не заменяет исчезнувшее измерение: проверяются реальные исходные
series и наличие всех нужных семейств, для rate также отсутствие пропавших рядов
в пятиминутной истории. Предупреждения значений, timestamp, traffic и истории
помечают результат неполным; их текст остаётся внутри backend.
Устаревание одного общего показателя не скрывает доступные соседние значения.
Периоды:
15m, 1h, 6h, 24h, 7d; сервер задаёт конец и шаг, не более 300 точек на ряд.
Пропуски образуют разрывы SVG. Видимая страница обновляется раз в минуту; скрытие
или уничтожение отменяет запрос, 401 прекращает polling и очищает показания.
SSR общей сводки имеет отдельный предел 1 с и при отказе сохраняет страницу.

## Каталог и расширение

| id | Семантика | Единица |
| --- | --- | --- |
| host.cpu | Загрузка CPU по rate idle за 5 минут | % |
| host.memory | RAM: 1 − MemAvailable / MemTotal | % |
| host.disk | Системный диск: 1 − avail / size; пороги 90/95% | % |
| backend.available | Успешность scrape backend | 0/1 |
| backend.join-ready | Готовность выдать JWT подключения | 0/1 |
| jvm.heap | Использованная heap | bytes |
| jdbc.pool | Активные соединения / максимум пула | % |
| jwt.issued | Успешные выдачи JWT в минуту | /мин |
| jwt.error-ratio | Ошибки / попытки за 5 минут | % |
| jwt.latency-p95 | p95 успешной выдачи JWT по histogram за 5 минут | мс |

JWT-показатели описывают выдачу токенов, не число звонков или качество media.
Для доли ошибок и p95 отсутствие запросов обозначается `no_traffic`. Некорректные
числа и знаменатели — отсутствие данных. Только admin получает точные значения;
обычный ответ имеет фиксированный DTO без queries, source, labels, объёмов памяти,
адресов, версий или событий. Все новые API и их ошибки — private, no-store.

Чтобы добавить показатель:

1. Проверить реально экспортируемую series, job, единицу, допустимую cardinality
   и правила безопасности. Если нужен collector, отдельно проверить его mounts
   и обновить оба overlay и конфигурационные guards.
2. Добавить определение в `MetricCatalog`: постоянный id, описание, unit, виды,
   фиксированный запрос и исходные samples для свежести. Текущий каталог рассчитан
   на один target каждого job; дополнительные targets требуют нового правила
   агрегации и теста, а не скрытого усреднения.
3. Добавить тест значений, sample freshness, down-target, пустоты и границ.
   Сверить query на Linux candidate. Обновить generated API при изменении DTO.
4. Администратор выбирает новый пункт в том же интерфейсе; новая ветка renderer
   для существующих единиц не нужна. Его выбор не расширяет общую сводку.

Удалённый из каталога id игнорируется при чтении прежних настроек с серверным
предупреждением и отвергается при новом сохранении.

## Приёмка и выпуск

Код подготовлен в `codex/cabinet-metrics`; production этим этапом не изменялся.
Release должен включать backend, frontend, V26 и monitoring overlay одного SHA.
Зафиксировать окончательный SHA после review, digests собранных application images
и предыдущий действующий release через существующий deployment-процесс. До
миграции нужен проверенный backup PostgreSQL. Нельзя подставлять исторический SHA
вместо текущего rollback-кандидата.

Локальные gates: `npm run verify`, `npm run frontend:verify:ssr`,
`gradlew.bat testContainer --tests '*MetricDashboardPostgresIntegrationTest'`.
Последний тест при недоступном Docker будет skipped, что не доказывает JSONB/CAS.
Браузерные fixtures проверяют frontend, но не заменяют реальные роли OIDC и БД.

Локальная проверка 2026-10-02: полный `npm run verify` прошёл, включая 657
frontend-тестов после исправлений итогового review, сборку, архитектурные границы, backend quality gates и 34
операционных Python-теста. SSR/resumability smoke прошёл отдельно. В настоящем
Chrome с синтетическим API проверены общий блок на главной, в профиле, комнатах
и встречах, запрет подробной страницы для всех четырёх остальных ролей,
добавление/вид/порядок/сохранение/повторное открытие, пустой набор и конфликт
двух вкладок. Мобильная страница и тёмная тема проверены визуально.
После review все 20 сгенерированных выражений freshness/range прошли
`promtool check rules` на закреплённом Prometheus 3.15.0. Изолированный
`promtool test rules` воспроизвёл исчезновение одного CPU-ряда при свежем `up`
и ещё вычисляемом rate: прежние выражения дали RED, исправленные — GREEN.
Тест передан через stdin существующему инструменту; конфигурация и данные
рабочего Prometheus не изменялись. Это проверка выражений с искусственными
samples, не приёмка реального exporter или нового release.

Docker Desktop в этой среде возвращает HTTP 500. PostgreSQL container test
пропущен; application images, их digests и Linux candidate здесь не собраны и
не приняты. Сохранённая Compose-конфигурация подготовлена из example env,
без runtime-секретов. До выполнения проверок ниже это кандидат исходного кода,
а не готовый к развёртыванию release.

Linux candidate перед выпуском должен подтвердить:

- `jitsi-node` и `jitsi-backend` UP; реальные имена JWT/JVM/JDBC series.
- Сопоставление CPU, MemAvailable и системного диска с VM; отсутствие внешнего 9100,
  UID без root, read-only mounts и отдельную ops_net.
- Все пять ролей получают только safe summary; admin query/catalog/prefs доступны
  только admin. Anonymous 401, operational roles 403, PUT без CSRF 403.
- Два первых INSERT и два UPDATE одной ревизии имеют по одному победителю;
  одинаковый subject в разных tenants не меняет чужие настройки.
- Остановка источника, старый sample и зависшее тело не блокируют кабинет;
  SSR укладывается в 1 с, подробный snapshot — в 3 с, очередь не растёт.
- Admin добавляет, удаляет, меняет порядок, сохраняет и повторно открывает страницу;
  мобильный экран, клавиатура, тёмная тема, Network и SSR не раскрывают labels.

После явно разрешённого выпуска проверить HTTPS, роли, свежесть и сохранение
настоящих данных. Внешняя проверка WebRTC с тремя участниками остаётся отдельной.

При откате вернуть предыдущие backend/frontend и monitoring overlay. V26 —
additive: оставить таблицу и Flyway history, не выполнять destructive rollback,
не удалять volumes. При отключённом Prometheus кабинеты продолжают работать.

Следующие отдельные этапы: Grafana для внутренних операторов с самостоятельной
авторизацией, реальные получатели оповещений вместо mock receiver, JVB/media и
сетевое качество, затем при доказанной необходимости Loki/Tempo.
