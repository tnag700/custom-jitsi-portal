## Совместимость и исправления

- TypeScript 7 вызывается явно в `build.types`, поэтому npm-ссылка `tsc` не
  может незаметно переключить сборку на старый компилятор. JS API TypeScript
  5.9.3 нужен существующим ESLint/OpenAPI; проверку типов он не выполняет.
  Это вариант [совместной установки, описанный Microsoft](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).
  Генерация OpenAPI сохранена, `--force` и `--legacy-peer-deps` не используются.
- Vitest оставлен на 4.1.11: Qwik beta.45 объявляет совместимость только с
  Vitest `<5`. Express, Qwik UI, Tailwind, Spring Retry и другие уже актуальные
  прямые зависимости не менялись ради изменения номера.
- Qwik теперь проверяется по npm-каналу `latest`: издатель обновляет его,
  тогда как `beta` отстаёт. Исправлены общий backend-адаптер и CLI-аудит;
  регрессионный тест сначала воспроизвёл ошибку.
- Удалён `vite-tsconfig-paths`: эту работу выполняет встроенный механизм
  Vite 8. Убрано ненужное разрешение install-скрипта esbuild.
- PMD 7 использует рабочий classpath и отдельный CLI classpath для CPD.
  Его блокирующие правила сохранены. Исправлены потеря исходной причины
  ошибок Redis/конкурентного расходования приглашений и закрытие ресурсов
  в тестовых утилитах. Полный PMD-аудит остаётся рекомендательным.
- Контейнерные тесты теперь используют те же PostgreSQL и Redis, что и
  production-кандидаты. Их временные порты привязаны к `127.0.0.1`.
  Для Testcontainers используются ссылки по digest: сочетание тега и digest
  его текущий парсер разбирает неправильно. Добавлена регрессионная проверка.
- Backend Dockerfile назначает владельца JAR при `COPY --chown`, исключая
  повторный слой с копией JAR при последующем `chown`.

## Ограничения и восстановление

Браузерный инструмент не смог проверить административную политику доступа.
Его ограничение не обходилось. HTTP/SSR и протокольная проверка OIDC не
являются доказательством реального браузерного входа или передачи WebRTC.
Jitsi остаётся на согласованном наборе `stable-11146-1`; переход всех четырёх
образов на `stable-11248` требует отдельной проверки реальной конференции.

Сервер имеет диск 30 ГБ. Удаляется только проверенный неиспользуемый build
cache по точным идентификаторам; рабочие образы, предыдущие runtime-образы,
посторонние проекты и их volumes сохраняются. Временные тестовые контейнеры
и volumes удаляются по проверенным именам/меткам.

Резервные копии и recovery-материалы остаются в закрытых каталогах сервера
вне Git. Для отката stateful-компонента используется восстановление снимка
вместе с прежним бинарником, а не запуск старого бинарника на изменённых данных.
