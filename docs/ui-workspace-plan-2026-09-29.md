# Единая рабочая область комнат и встреч

Цель: показать связь «комната содержит встречи» и убрать необходимость переключаться между двумя разделами.

1. Один пункт меню «Комнаты и встречи», существующий `/meetings` остаётся основным адресом. Старый `/rooms` доступен по прямым ссылкам.
2. На странице до шести карточек комнат, внутри каждой до трёх плиток встреч с датой и статусом. Полное расписание выбранной комнаты раскрывается внутри её карточки, с прежней пагинацией, участниками и приглашениями.
3. Создание встречи сразу в выбранной карточке; создание, редактирование, закрытие и удаление комнаты через существующие диалоги. Закрытые комнаты доступны для просмотра истории, без создания встреч.
4. Переиспользовать API и компоненты. Не менять права, контракты, зависимости или backend. Ошибка превью отличается от пустой комнаты. Число запросов ограничено размером страницы.
5. Проверки: базовые 571 frontend-тестов прошли; регрессии на вложенность, страницы и закрытые комнаты; frontend tests, typecheck, lint, production build; браузерная проверка desktop/mobile и диалогов на локальном тестовом API.

Рабочая ветка: `codex/rooms-workspace`, база `70f1f3f`. Админская навигация и выделение диалогов выполняются отдельными ограниченными подзадачами в этой же ветке.

## Администрирование и общие диалоги

- Две строки вкладок заменены одной навигацией: обзор и диагностика, пользователи и доступ, настройки системы. На широком экране навигация сбоку, на узком — над содержимым. У разделов есть краткие пояснения; текущий раздел выделен, включая страницы конкретных инцидентов.
- Права, ссылки возврата, выбранная среда и уведомления об обновлениях сохранены. Убран повторяющийся крупный заголовок консоли; добавлена клавиатурная ссылка к содержимому.
- Диалоги комнат вынесены в общий `RoomManagement` для обеих страниц. Существующие формы, серверная валидация, ошибки и подтверждения удаления используются повторно.
- Удаление открытой комнаты возвращает к сетке до повторной загрузки данных. Недоступная активная конфигурация блокирует создание комнаты, сохраняя просмотр и работу с существующими встречами.

## Выполненные проверки

- Node 24.21.0: frontend Vitest — 79 файлов, 589 тестов успешно.
- TypeScript, production-сборка клиента и SSR-сервера, ESLint — успешно.
- Строгие проверки слоёв/архитектуры и `git diff --check` — успешно.
- `scripts/verify-ssr.mjs` — успешно; эта проверка покрывает базовую выдачу SSR и загрузку Qwik-ресурсов, а не пользовательские клики.
- Независимое ревью: исправлены зависимость просмотра от активной конфигурации и возврат после удаления выбранной комнаты; повторное ревью не выявило других конкретных дефектов.
- Временные локальные серверы остановлены. После проверки пользователь разрешил публикацию на production; выпуск ограничен фронтендом с сохранением предыдущего образа для отката.

## Ограничение проверки

Браузерный инструмент дважды отказал в доступе к локальному тестовому сайту: не удалось проверить административную политику браузера. Контроль не обходился. Проверка реальной раскладки desktop/mobile и кликов в браузере остаётся незавершённой; тесты компонентов и SSR не заменяют её.
